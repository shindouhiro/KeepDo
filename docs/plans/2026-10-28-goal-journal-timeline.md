# 每日目标图文日记与时间线实施计划

**目标：** 点击每日目标进入对应日期的记录面板，填写进展、上传图片，按日期回顾该目标的时间线，并支持编辑与大图查看。

**架构：** `GoalJournalDialog` 编排目标、所选日期、编辑器和时间线；`GoalJournalEditor` 管理文字、待上传图片和保存状态；`GoalJournalTimeline` 只展示记录并发出编辑事件。`useGoalJournal` 负责分页加载与请求竞态；独立 Pinia 日记索引负责日历的历史记录可见性。记录和图片保存到独立 D1 表，沿用当前会话认证，不扩大基础业务 JSON。

**技术栈：** Vue Composition API、TypeScript、Pinia、Tailwind、现有 Workers/D1，无新增运行时依赖。

## 关键决策

- 采用现有 D1 存储压缩图片，避免引入尚未配置的对象存储或付费资源；单张限制 400 KB，每条最多 6 张，客户端最长边缩至 1600px。图片量扩大时可将图片接口背后的存储替换为 R2，而不改变页面记录模型。
- 记录以账号、目标、业务日期关联，一天可有多条，按日期、创建时间、ID 倒序分页；已有打卡日期与日记日期在目标达成后仍能从日历回看。
- 文字与图片以单次受限 multipart 请求保存；D1 batch 原子提交记录、图片新增和图片移除。编辑带版本号与操作 ID，防止其他设备覆盖和重试重复提交。
- 每个读写和图片接口均校验当前用户所有权；上传检查字节大小、真实文件签名和图片数量，禁止 SVG/HTML；私有图片响应不缓存、不嗅探。
- 保存失败保留草稿，切换日期/关闭时提示未保存内容；异步结果按目标隔离，避免快速切换时串记录。图片预览 URL 在移除、保存和退出时释放。
- 编辑记录与打卡分开，写日记不会悄悄改变目标累计进度。现有基础 JSON 备份仍覆盖目标、习惯和待办，图文日记独立保存，须在说明中明确备份范围。

## 实施步骤

1. 增加日记与图片表迁移、共享类型和校验、受限请求读取及认证后的 CRUD/图片/索引接口。
2. 添加真实本地 API 测试，覆盖创建图文、分页、编辑保留/移除图片、冲突与幂等、账号隔离及非法上传。
3. 接入日历目标直达面板、日期详情入口、历史索引和精细图文时间线；补充浏览器图片压缩及草稿管理。
4. 验证本地真实上传、刷新回看、编辑、失败保留、分页、手机与深色布局；运行类型检查、单元测试、API 测试与发布预检。
5. 应用线上迁移，发布现有 Worker，检查实际静态资源和登录保护；不写入生产用户测试日记。

## 验证结果

- `pnpm test`：29 项单元测试通过；`pnpm test:api`：9 项真实 Workers/D1 测试通过，包含图文保存与重新读取、图片账号隔离、非法文件与大小限制、保留/移除图片、版本冲突、并发幂等和分页。
- 类型检查、生产构建与 Wrangler dry-run 通过；日记面板按需加载，未增加运行时依赖。
- 使用独立本地测试账号验证：日历目标直达、文字加图片及纯图片保存、自动压缩预览、大图查看、编辑时保留图片、刷新后内容与图片保留。
- 保存失败场景使用测试账号临时缺失目标模拟，草稿保留；随后已恢复测试数据。未改动生产账号或浏览器原有登录会话。
- 草稿关闭保护采用站内原生 dialog，继续编辑会保留草稿；保存后编辑器收起，为时间线留出空间。
- 检查了 1280px 桌面、390px 手机与深色模式，日记面板内部无横向溢出，照片正常加载，无重复 ID 或新增控制台异常。
- 独立测试服务器已停止，临时配置已清理；预览截图保存在 `/tmp/keepdo-goal-journal-timeline.png`。
