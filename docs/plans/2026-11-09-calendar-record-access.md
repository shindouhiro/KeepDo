# 日历全部事项与记录入口优化

**目标：** 解决周视图只渲染前两项、月视图只渲染第一项，导致其余目标或习惯无法直接打开记录的问题。

**方案：** 复用 `CalendarPlanner` 的单日滚动列表和 `CalendarPlanItem` 的记录事件，每天始终渲染全部计划，紧凑与完整模式只影响标题展示和列表高度，不影响事项数量。保留日程详情作为集中查看入口。

## 实施与验证

1. 移除周/月视图的条数截断，为单日列表添加高度上限、键盘焦点、滚动提示与完整事项数量。
2. 目标和习惯卡片提供可见的「记录 / 时间线」提示，单击卡片直接打开对应主体与日期的日记；待办继续打开日程详情。
3. 更新 README，运行 `pnpm test` 和 `pnpm build:cloudflare`。
4. 浏览器使用至少三个习惯验证周/月视图的第三项可滚动找到并打开记录；检查手机布局、完整卡片与日程详情、目标打卡独立性。
5. 修复双击入口时第二次点击落在新弹窗遮罩上导致立即关闭的问题，保留正常单击遮罩关闭行为。

## 验证结果

- 独立本地测试账号包含 1 个目标、3 个习惯与 1 个待办。周视图与月视图均保留当天全部 5 张卡片，列表独立滚动。
- 第三个习惯可单击、双击或用 Enter 打开日记，保存 Markdown 记录成功；写记录后仍为 0/1，未自动打卡。
- 修复前在月视图重现双击后日记立即关闭；修复后弹窗保持打开，普通单击遮罩仍可关闭。
- 待办进入当日日程详情，完整/紧凑模式都保留 5 项。
- 390px 手机视口内可打开第三项日记，页面无横向溢出；横向滚动仅保留在日历容器内。浏览器控制台无警告或错误。
- 桌面与手机截图分别保存为 `docs/screenshots/calendar-all-plans-desktop.png`、`docs/screenshots/calendar-all-plans-mobile.png`。
- `pnpm test`：57 项通过；`pnpm build:cloudflare`：类型检查与生产构建通过。

## 打卡完成颜色区分

- 日历卡片按完成状态动态配色：目标以当天打卡为准，习惯以当天次数是否达到目标为准，待办以完成状态为准。完成后统一使用绿色背景、边框与目标进度条，撤销后恢复类型配色。
- 保留已打卡、已完成文字及勾选图标，并在周/月视图共用图例中补充绿色状态说明；目标累计达成不代表当天已打卡。
- 本地临时验证页挂载实际 `CalendarPlanner`，验证三类卡片完成变绿、撤销恢复、累计已达成但当天未打卡保持原色；手机深色月视图验证通过，页面宽度与滚动宽度相同，横向滚动仅发生在日历容器内，控制台无错误或警告。
- `pnpm test`：60 项通过；`pnpm build:cloudflare`：类型检查与生产构建通过。
