# KeepDo 账号与 D1 持久化设计及实施计划

**目标：** 使用用户名和密码注册、登录，登录后访问当前账号的目标、习惯和待办，部署在现有 Cloudflare Worker。

**架构：** Vue 负责交互；同源 Workers API 负责认证和数据授权；D1 存储用户、会话与账号数据。数据库是业务数据来源，浏览器只保留主题设置及尚未迁移的旧版本数据。

**技术栈：** Vue 3 Composition API、Pinia、TypeScript、Workers、D1、Node 原生密码学 API、Zod、pnpm Catalog。

## 设计取舍

- 继续使用 Workers + D1，避免新增其他云服务。外部 Postgres 可用于未来更复杂的数据分析，目前没有必要。
- 用户名密码方案使用原生 scrypt 加独立随机盐，随机会话令牌仅将 SHA-256 摘要存入数据库；不自创加密算法。相比引入包含邮箱模型的认证框架，此方案只实现已确定的用户名注册、登录和退出。
- 用户数据以经过校验的 JSON 文档保存，复用现有 AppData 结构，使用递增版本和条件更新防止多设备静默覆盖。未来按查询规模需要再拆分业务表。
- 会话放在 HttpOnly、Secure、SameSite Cookie 中。所有数据访问从服务端会话获取 user_id，前端不能指定其他用户。
- 修改请求校验同源 Origin；SQL 采用参数绑定；登录与注册实施数据库计数限流；错误不泄露 SQL、密码或会话。
- 界面明确展示保存中、已保存和失败；写入串行执行。冲突时保留未保存内容，允许导出，并提示先处理冲突，不能自动覆盖服务器数据。
- 本地旧数据不自动上传。首次登录可以选择迁移旧数据，导入前确认覆盖，并保留原始本地备份。

## 组件边界

- App：恢复会话并组合登录页或工作区。
- AuthView：用户名密码注册和登录表单，显示校验与请求状态。
- KeepDoWorkspace：现有应用界面，加载账号数据，保持业务组件职责。
- AccountBar：账号、保存状态、重试、刷新和退出；退出前等待保存。
- 账号 store：会话恢复、注册、登录和退出。
- KeepDo store：业务状态与版本、串行持久化、失败恢复和旧数据迁移。

## 实施步骤

1. 新增共享数据校验、D1 迁移、原生密码与会话模块、限流及同源 API。
2. 为后端配置独立类型检查，接入 Wrangler D1 绑定与本地开发命令。
3. 新增登录界面与账号状态，将原有工作区挂载在认证之后。
4. 将浏览器业务持久化替换为数据库读取与版本条件写入，保留 JSON 导入导出。
5. 更新设置文案、旧数据导入提示、使用与部署说明。
6. 在本地 D1 上验证注册、错误密码、会话、退出、两个用户的数据隔离、持久化、版本冲突、非法输入和跨站请求拒绝。
7. 检查构建与 dry-run，再创建项目 D1、执行迁移、发布现有 Worker；线上验证 API 与静态资源。生产验证使用专用临时测试账号，不读取用户个人数据。

## 验收

未登录 API 返回 401；错误密码无法登录；密码与令牌不以明文保存；不同账号独立；重新登录可读取已保存数据；过期版本返回 409；保存失败可见；旧本地数据不会静默迁移；生产仍使用原有 URL。
