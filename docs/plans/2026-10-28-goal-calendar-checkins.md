# 目标日历快捷打卡实施计划

**目标：** 设定目标后可在周历、月历和日期详情直接打卡并显示对应日期的标记，支持撤销和账号同步。

**架构：** `CalendarPlanItem` 展示计划并转发打卡事件，`CalendarPlanner` 转发目标 ID 和日期，`TodayView` 调用 Pinia。`GoalCheckInButton` 复用打卡、已打卡、未来日期禁用状态；`CalendarGoals` 在当日列表和详情复用它。共享函数负责天数去重、校验和日期记录，Pinia 沿用已有保存队列与错误提示。

**技术栈：** Vue 3 Composition API、TypeScript、Pinia、Tailwind CSS、现有 Node 测试，无新增依赖。

## 数据约定

- `Goal.checkIns` 为可选的日期到布尔值映射，兼容旧账号和备份；服务端校验并保存到现有 JSON 数据，不新增数据库表。
- 天数型目标按日期累计；同一目标当天的直接打卡与关联习惯只贡献一天。撤销仅移除对应贡献，保留其他来源和原有累计值。
- 数值型、里程碑型打卡只标记当天行动，避免假定具体完成数量或阶段。
- 禁止提前打卡和创建日之前打卡；已记录日期在目标达成后仍展示，支持查看和撤销。
- 打卡状态与目标整体达成状态分开展示，既有习惯/待办行动完成率保持原有统计口径。

## 实施步骤

1. 为日期记录、历史可见性、天数去重与撤销、数值/里程碑不改进度、旧数据兼容及非法记录添加测试。
2. 扩展目标类型和服务端 schema；实现共享日期打卡函数，接入目标及习惯的 Pinia 操作。
3. 添加复用按钮，接入日历、当日目标列表与日期详情；所有入口使用唯一 ID 和清晰状态。
4. 运行 `pnpm test`、`pnpm build:cloudflare`，通过独立本地测试页面验证真实点击、周/月同步、移动布局、账号保存与刷新。

## 验证结果与视觉调整

- 根据用户要求，日历打卡采用右上角 18px 细圆圈与 28px 点击区域；已打卡显示绿色勾选和文字标记，不使用整行大按钮。习惯按钮缩小为 32px，去除渐变和厚重阴影。
- `pnpm test`：24 项通过；`pnpm test:api`：8 项通过，真实本地 Workers/D1 保存后重新读取保留目标日期记录。
- Vue 和 Worker 类型检查、生产构建、Wrangler dry-run 均通过。
- 独立 Vue 页面验证新建目标即时显示、直接打卡不打开详情、关联习惯去重、补卡、撤销、目标达成后记录保留、日期详情与周/月视图同步、刷新后保留。测试未改动用户账号数据。
- 1280px 桌面、390px 手机和深色模式检查通过；月历仅在自身容器横向滚动，绘制范围限制防止整页溢出；无重复 ID，最终测试页面无新增控制台警告或错误。
