# 页面手动授权

用户要求直接在页面完成 GitHub 授权。保留现有已配置密钥时的加密保存流程，新增无需服务端密钥的本次页面授权，避免通过网页设置部署密钥或在数据库中明文保存令牌。

## 组件与接口边界

- `GitHubBackupPanel` 展示连接状态、操作反馈和历史；继续向设置面板上报 busy。
- `GitHubConnectionForm` 独立展示授权步骤及输入，使用 owner/repo/token 双向绑定，发出 connect 事件。
- `useGitHubBackup` 按站点是否配置密钥选择持久连接或页面连接；页面令牌只在闭包中保留，关闭设置或断开时释放，提交后的输入框清空。
- `POST /api/github-backup/session` 使用经过校验的动作 connect/history/upload/read，共用现有 GitHub 客户端、私有仓库复核、固定账号路径、大小限制和限流；不会写入连接表。
- 所有动作经过已有登录与同源校验。授权不放入 URL、日志、浏览器存储或备份文件。

## 验证

- 无密钥情况下验证连接、上传、历史读取、恢复和账号隔离，以及非法输入、公开仓库和方法拦截。
- 真实 GitHub 私有测试仓库使用合成数据验证新接口；页面验证无密钥表单、输入禁用、错误反馈和清空行为。
- 运行单元测试、API 集成测试、前后端类型检查与生产构建。

## 验证结果

- 52 项单元测试、15 项 API 集成测试全部通过，前后端类型检查与生产构建通过。
- 无服务端密钥时，通过真实 GitHub 完成 9 项流程检查；合成数据提交为 `5f4729375c38545666e6b5f70d714fd2b851a6ff` 和 `618c3ce8e0ca6b1fc03ccf9c42c43cbab78d6a80`，仓库为 `shindouhiro/keepdo-backup-test`。读取两版内容与原数据一致，旧版恢复后日记及图片字节校验通过，连接状态始终无持久授权。
- 浏览器验证无密钥时表单可见，非法令牌有友好反馈，提交期间禁用其他数据操作，结束后清空令牌；关闭再打开设置时输入已清空。390px 手机与 1280px 桌面布局可用，无控制台错误或警告。
- 本次仅更新本地代码与测试页面，未部署线上。
