# 原生安装包发布修复

## 目标与原因

`v1.0.2` 已完成所有平台构建，但原生工作流只上传 Actions Artifacts，Release 发布步骤仅附加 Chrome 扩展。用户需要在同一 Release 的 Assets 中直接下载 DMG、EXE、APK 等安装包。

## 实施方案

- 保留原生构建，增加独立发布工作流：监听成功的标签构建，并允许通过标签与原构建 ID 手动补发。
- 在 GitHub runner 内下载和发布产物，避免本机大文件上传连接超时；不重新编译已有成功产物，不移动已发布标签。
- 校验仓库、工作流、构建结论、标签提交、应用版本及六组原生产物；只提取七个最终分发文件，生成 SHA-256 校验和。
- 使用默认分支上的发布脚本，不执行构建产物内容。缺失或重复安装包时停止发布。
- 扩展与原生流程共用说明，兼容并发创建 Release，重复补发只替换同名附件。

## 验证与交付

- 覆盖构建来源错误、失败构建、标签格式错误、安装包缺失或重复、符号链接及成功收集等测试。
- 校验 YAML、完整单元测试和脚本语法，再发布修复并为 `v1.0.2` 补传安装包。
- 最终核对线上 Release 中各附件的名称、大小、上传状态及可用校验和。
